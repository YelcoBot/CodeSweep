## Dependencias entre proyectos

```
CodeSweep ──► Infrastructure.VisualStudio ──► Infrastructure.Roslyn ──► Application ──► Domain
    │                                                                      ▲
    └──────► Infrastructure.Sql ──► SqlEngine (solo el contrato ISqlEngine)┘
```

- **Domain**: no conoce a nadie. Las reglas universales y de markup viven aquí (texto puro).
- **Application**: solo Domain. Define los puertos y el orden de las fases.
- **Infrastructure.Roslyn**: implementa `ICodeCleaner`. Depende de Roslyn, no de VS.
- **Infrastructure.Sql / SqlEngine**: implementan `ISqlFormatter`. SqlEngine no referencia nada de CodeSweep.
- **Infrastructure.VisualStudio**: todo lo que necesita VS/SSMS (editor, opciones, guardado, `ISqlCleaner`).

## Enrutamiento

`DocumentRouter` decide por archivo; `CleanupOrchestrator` ejecuta las fases en este orden.

| Archivo | Motor | Cómo |
|---|---|---|
| `.cs`, `.vb` (incluye `.aspx.cs` / `.aspx.vb`) | **Roslyn** | Background, en paralelo, un solo `TryApplyChanges` |
| `.sql` | **Sql** | Background: ScriptDOM (AppDomain aislado) + reglas universales; buffer si está abierto, si no el disco |
| `.aspx`, `.ascx`, `.master`, `.asax`, `.cshtml`, `.razor`, `.html`, `.xml`, `.config`, `.xaml`, `.css`, `.js`, `.ts`, `.json`… | **Editor** | Secuencial en el hilo de UI: abierto → editor invisible → (pregunta) ventana real |
| Generados, patrones excluidos, T4 | **Skip** | No se tocan |

En **SSMS** solo se procesa SQL (`SweepOptions.RestrictToSql()`), y Tools → Options oculta los demás lenguajes con `visibleWhen` + un UIContext que activa el paquete.

## Formato T-SQL

- **ScriptDOM forzado:** el motor corre en un AppDomain con base en la subcarpeta `SqlEngine\` del VSIX. Así siempre usa nuestro ScriptDOM (la última versión), también en SSMS, que trae otro con la misma identidad 18.0.0.0. El dominio principal nunca carga ScriptDOM ni EditorConfig.
- **Prioridad de cada opción:**
  1. `.editorconfig` `[*.sql]`, con el paquete `editorconfig` y las mismas claves que SSMS.
  2. Opciones del producto: se detectan leyendo los manifiestos de `SettingsManifests` (las `sqlFormatter.*` de SSMS).
  3. Opciones de CodeSweep (`SqlFormatterCatalog`).
- **Render:** CodeSweep solo muestra las opciones que el producto no tiene. En VS se ven las 58; en SSMS 22.10, 4.
- **Seguridad:** no se formatea si hay errores de sintaxis o SQLCMD, y el resultado se descarta si pierde comentarios o no vuelve a compilar.

## Tools → Options

| Producto | Dónde | Cómo se lee |
|---|---|---|
| VS 2026 / SSMS 22 | Interfaz moderna (`CodeSweep.registration.json`) | `settings.json` de la instancia (`VsSettingsStore`) |
| VS 2022 | Página clásica (`ClassicOptions`) | `BaseOptionModel` |

Al cambiar `CodeSweep.registration.json` hay que subir el `CacheTag` de `CodeSweep.Settings.pkgdef`; `Update-SqlFormatterOptions.ps1` lo hace solo.

## VSIX

- **Versión:** el manifiesto queda fijo en `1.0.0` y el pipeline pone la real al publicar. Para builds locales: crear `src/YelcoBot.CodeSweep/version.local.props` (ignorado por git) con `<Project><PropertyGroup><LocalVsixVersion>1.10.1</LocalVsixVersion></PropertyGroup></Project>` y subir ese número; el target `ApplyLocalVsixVersion` la aplica solo al manifiesto dentro del VSIX (`obj`), nunca al del repo.
- **DLLs extra:** DI 10.0.10 y `Microsoft.Bcl.AsyncInterfaces` en la raíz, porque el VSSDK las omite. El motor SQL y sus dependencias van solo en `SqlEngine\`; ver el target `IncludeExtraFilesInVsix` del `.csproj`.
- **Dos paquetes, mismo código:** el Marketplace de Visual Studio rechaza el destino `Microsoft.VisualStudio.Ssms` (`Could not find matching sku`), así que el manifiesto del repo solo declara Visual Studio.
  - **Marketplace** (pipeline): build normal, solo Visual Studio.
  - **GitHub Releases** (https://github.com/YelcoBot/CodeSweep/releases): build con `IncludeSsmsTarget=true` (en `version.local.props` o `-p:IncludeSsmsTarget=true`). El target `AddSsmsInstallationTarget` agrega SSMS 22.7+ al manifiesto dentro del VSIX (`obj`). Ese `.vsix` se instala en VS y SSMS.
- **Instalación:** cada producto instala su copia por separado. Si al hacer doble clic se abre el instalador de SSMS, solo ofrece SSMS: para VS, usar el `VSIXInstaller.exe` de VS.
